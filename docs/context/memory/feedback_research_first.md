For any significant product, UX, or architecture decision, Vishesh wants a
**complete analysis + deep research** (web + competitive teardown of the best
tools) on the best approach BEFORE implementing — grounded in the real pain
points faced by millions of developers. Then implement with **best-in-class UI**
(top-tier polish, not just functional).

**Why:** the product only wins if it genuinely rectifies widespread dev pain;
half-researched decisions produce mediocre features that won't convert.

**How to apply:** before building a non-trivial decision, launch parallel
research agents, synthesize into a clear recommendation, then implement with
strong UI craft. Don't ask the user to choose blind — research it and recommend.
Cheap/clear-cut changes don't need this; reserve it for decisions that shape the
product. See [[project_business_goal]], [[project_review_architecture]].
